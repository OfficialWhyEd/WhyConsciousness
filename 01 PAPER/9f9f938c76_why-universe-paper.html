§ 1

Abstract & Visione Strategica

Questo documento è un portfolio tecnico ad alta densità che censisce, analizza e contestualizza l'intero ecosistema software costruito sotto l'identità whyed.

Il presente documento cataloga quindici sistemi software distinti, tutti progettati e implementati da Edoardo (@whyed). L'ecosistema spazia dal controllo DAW via plugin VST3/AU al motion graphics programmabile in React/TypeScript, dall'automazione completa del content marketing per social media (IG, TikTok, YouTube) al controllo AI di emulatori Game Boy Advance. La filosofia architetturale unificante è macOS-native (Tauri, JUCE, Electron) e AI-first by design — l'intelligenza artificiale non è un layer opzionale ma il sistema nervoso centrale di ogni applicazione. Ogni progetto risolve un problema concreto e immediato nel flusso di lavoro creativo/tecnico dell'autore, con architetture che privilegiano la velocità di iterazione, la modularità e l'estensibilità.

Cronologia & Roadmap

L'ecosistema si è evoluto in quattro ere distinte, ciascuna caratterizzata da un salto qualitativo nell'ambizione tecnica e nella sofisticazione architettuale.

Era 1 · Origini
WhyCremisi fase beta — primissima versione VST3 con AI multi-provider su JUCE 7. Collaborazione con Carlo/Aura (Linux backend). Proof-of-concept del bridge OSC↔WebSocket↔React. Definisce il paradigma "plugin = layer intelligente sul DAW". Il Remotion Video Workflow nasce come infrastruttura base per tutti i video futuri.
Era 2 · Ecosistema Why — Fine 2025
Nasce il brand Why. WhyCavalry porta l'AI nel motion graphics via MCP file-bridge. WhyPost diventa il progetto più complesso: 15 agenti Python, 10 cron jobs, Mission Control React full-stack, pipeline EXEL→SCRIPT→ASSET→CLACK→SAFETY→PUBLISHER.
Era 3 · Espansione macOS — 2026
WhyCalendar porta l'AI nella gestione del tempo con stile biomeccanico e mascotte WhySpidey. WhyEmuGBA sperimenta il controllo AI di videogiochi via MCP/WebSocket + mGBA WASM. cornettino-facts (2026-05-19) — primo video verticale completato con karaoke sincronizzato.
Era 4 · Tool & Agent Layer — 2026
HyperFrames, Raincast, Screenpipe installati come tool di sistema. Designo emerge come agente design specializzato con 5 skill UI in parallelo. CLACK evolve da semplice renderer a agente editor autonomo con memoria editoriale. WhySpidey si consolida come mascotte modulare del brand con pipeline Remotion dedicata.

§ 4

WhyCremisi

L'evoluzione della fase beta. Non è un effetto audio — è un layer di controllo e intelligenza sopra il DAW.

WhyCremisi
Plugin VST3+AU+Standalone · JUCE 8 · 6 Provider AI · Flight Recorder JSONL · BotFace mascotte
Attivo VST3/AU

WhyCremisi è il plugin definitivo per il master channel — non è un effetto, non è un utility plugin. È un sistema cognitivo che osserva ogni azione del producer, la registra in un flight recorder JSONL append-only (O(1) per evento), parla con 6 provider AI contemporaneamente e controlla il DAW via OSC (Ableton Live, REAPER, Bitwig). Il frontend React 19 è costruito attorno alla mascotte BotFace — una faccia SVG animata con 9 stati emotivi che deve essere "sempre viva" (glow pulsante, pupil drift, scan-line su transizioni di stato, reactive rings al ricevere risposte AI). AU format aggiunto il 09/05/2026 per compatibilità Logic Pro / GarageBand. 14/14 test automatizzati pass sul plugin reale.

§ 5

WhyCavalry

MCP Server per Cavalry — il file bridge che porta Claude nel motion graphics.

WhyCavalry
MCP Server TypeScript · File Bridge · 17 tools · App Electron standalone · 7 motion templates
Completato MCP

WhyCavalry risolve un problema fondamentale: Cavalry (app professional motion graphics macOS) non espone né HTTP API né AppleScript avanzato. La soluzione è un file bridge elegante: il server MCP scrive comandi JSON in ~/.whycavalry/cmd/; uno script JS incollato nel Script Editor di Cavalry polling quella cartella, esegue i comandi e scrive i risultati in ~/.whycavalry/res/. Claude legge i risultati come tool output. Include anche /Applications/WhyCavalry.app — un'app Electron standalone con chatbot integrato che invia comandi a Cavalry senza passare da Claude, con icona personalizzata dal logo di Edoardo.

WhyPost
15 agenti Python · 5–7 video/giorno · IG + TikTok + YouTube Shorts · Roadmap 100%

WhyEmuGBA

Bridge real-time tra intelligenza artificiale e Game Boy Advance.

WhyEmuGBA
Node.js + TypeScript + MCP JSON-RPC · mGBA WASM in browser · 20 tools · 6 sub-agents AI
In sviluppo MCP

WhyEmuGBA è un esperimento radicale: far giocare Claude a giochi Game Boy Advance. Un server Node.js sulla porta 9876 serve mGBA WASM in browser ed espone 20 MCP tools (get_screen, press_button, skip_frames, read_memory, ecc.) che permettono a Claude di vedere lo schermo GBA e premere tasti. 6 sub-agents specializzati: Vision (analisi schermata), Battle (combattimento), Explorer (navigazione mappa), Text (lettura dialoghi), Controller (input fisici), Memory (lettura RAM GBA per stato di gioco reale). Progetto preso in mano da Claude Code dopo che opencode aveva fallito per context overflow.

CLACK

Agente editor video autonomo — analisi virale, karaoke, memoria editoriale.

CLACK
Agente editor autonomo · Karaoke word-level · Analisi TikTok/IG viral · clack_memory.json
Parte di WhyPost

CLACK non è un semplice renderer — è un agente editor con autonomia totale e memoria propria. Studia i video più virali di TikTok/Instagram scaricandoli con yt-dlp, analizza hook timing, motion graphics, cut rhythm e audio energy tramite claude -p, e salva ogni insight in data/clack_memory.json per usarli nei render futuri. Le karaoke captions sono generate parola per parola, sincronizzate al millisecondo usando i timestamp di edge-tts SubMaker. L'obiettivo dichiarato: video indistinguibili da creators con 1M+ follower. Integra 3 template Remotion (WhyMultiTemplate, WhyTutorialTemplate, WhyBestOfTemplate).

§ 16

Strategie Prioritarie & Analisi Architettuale

Analisi trasversale dell'ecosistema — pattern comuni, punti di forza, priorità di sviluppo e raccomandazioni strategiche per massimizzare l'impatto tecnico e creativo.

Zero-cost AI Architecture

Il vincolo più intelligente dell'intero ecosistema: tutti i 15 progetti usano Claude Pro esistente tramite claude -p headless invece di API key separate. WhyPost genera 5–7 video/giorno con meno di 10 call Claude. Questo ha forzato ottimizzazioni architetturali reali: batch processing, buffer strategico da 7 giorni, Claude Opus solo 1 volta/settimana (domenica), Sonnet per tutto il resto. Raccomandazione: estendere questo pattern anche a WhyCalendar e WhyEmuGBA per mantenerli cost-free a lungo termine.

File Bridge come Primitiva di Integrazione

WhyCavalry introduce il file bridge pattern — una primitiva universale per integrare applicazioni che non espongono API. Il pattern (cmd/ in, res/ out, polling ogni N ms) è applicabile a qualsiasi app macOS. WhyCremisi usa invece WebSocket RFC 6455 per comunicazione bidirezionale in tempo reale. Raccomandazione: codificare queste due primitive (file bridge + WebSocket bridge) in una libreria TypeScript riutilizzabile per futuri progetti Why.

Flight Recorder come Memoria Persistente

Il sistema JSONL append-only di WhyCremisi (sessions/YYYYMMDD_HHMMSS/events.jsonl) risolve elegantemente il problema della memoria AI: ogni prompt inviato al DAW AI include automaticamente gli ultimi 200 eventi di sessione come contesto. Il formato JSONL è O(1) per scrittura, non richiede lock file, è leggibile da tool Unix standard. Raccomandazione: adottare questo pattern di "memoria contestuale automatica" anche in WhyPost (ultime N pubblicazioni come contesto per SCRIPT) e WhyCalendar (log eventi giornata).

Agenti Specializzati vs Agente Generalista

WhyPost dimostra la superiorità degli agenti specializzati: 15 agenti con responsabilità singola (EXEL fa solo scraping, SCRIPT fa solo script writing, ecc.) vs un singolo agente generalista. Ogni agente è testabile in isolamento, sostituibile senza impatto sugli altri, monitorabile indipendentemente. Il costo: orchestrazione più complessa (MAIN + crontab + state.json). Raccomandazione: applicare la stessa filosofia di decomposizione a WhyCremisi (separare AiEngine, SessionManager, OscBridge in processi distinti) e WhyEmuGBA (i 6 sub-agents sono già sul percorso giusto).

Native macOS come Vantaggio Competitivo

Tutti i progetti con interfaccia utente sono app macOS native: Tauri v2 (WhyCalendar, Raincast), Electron (WhyCavalry), JUCE Standalone (WhyCremisi). Nessuno è una web app in un wrapper. Questo porta: performance nativa, accesso a API di sistema (audio, permessi, file system), integrazione con l'ecosistema macOS (traffic light, AppleScript, NSFileManager). Raccomandazione prioritaria: WhyPost Mission Control (React su localhost) è l'unico progetto non nativo. Wrapper Tauri su localhost:5173 porterebbe notifiche native macOS per eventi critici (buffer < min_days, publish failure).

Mascotte come Sistema di Design Vivente

WhySpidey e BotFace non sono decorazioni — sono interfacce emotive. BotFace comunica lo stato AI in modo istantaneo e comprensibile senza leggere testo. WhySpidey porta personalità in un'app di calendario altrimenti asettica. La regola "BotFace appare SOLO accanto all'ultimo messaggio bot" evita confusione e mantiene il focus visivo. Raccomandazione: estendere WhySpidey come mascotte del brand Why completo — ogni app della famiglia potrebbe avere WhySpidey in un angolo con comportamenti contestuali diversi per app.

Filosofia di adozione tool:

Ogni tool nel toolbox risponde a una domanda reale, non a tendenze. La regola: se Claude Code può bridgiarlo, entra nell'ecosistema. Il risultato è un ambiente dove tutto comunica — Obsidian via MCP, Cavalry via file bridge, Gmail via MCP, Calendar via OAuth — con Claude Code come hub centrale di orchestrazione.

Il Mac è il cervello creativo (audio, video, plugin, app native). Windows è il muscolo computazionale (GPU, ML training, gaming research). Ubuntu è l'infrastruttura silenziosa (server, daemons, deployment). Tre ambienti, un solo flusso di lavoro coerente.
