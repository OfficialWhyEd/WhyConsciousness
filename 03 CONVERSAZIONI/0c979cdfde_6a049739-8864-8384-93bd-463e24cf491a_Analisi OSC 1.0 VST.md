# COSA È OSC DAVVERO

OSC = protocollo basato su messaggi.

È pensato per mandare dati in tempo reale tra applicazioni attraverso rete o socket.

Esempio:

```text
/synth/filter/cutoff 0.75
```

oppure

```text
/player/jump
```

oppure

```text
/ai/emotion sadness
```

La cosa potente è che OSC:

- è gerarchico
- leggibile
- molto più flessibile di MIDI
- supporta tipi multipli
- può inviare bundle sincronizzati temporalmente

---

# DIFFERENZA ENORME TRA MIDI E OSC

| MIDI | OSC |
|---|---|
| Limitato | Estremamente flessibile |
| 7-bit spesso | float32 reali |
| Struttura rigida | Address system dinamico |
| Hardware anni 80 | Pensato per reti moderne |
| Messaggi fissi | Namespace personalizzati |

OSC è quasi “internet-native”.

---

# STRUTTURA DI UN MESSAGGIO OSC

La spec divide tutto in:

1. Packet
2. Message
3. Bundle

---

# 1. OSC PACKET

Unità base trasmessa sulla rete. citeturn0search0turn0search12

Può contenere:

- un messaggio
- oppure un bundle

---

# 2. OSC MESSAGE

Formato:

```text
[address pattern]
[type tags]
[arguments]
```

Esempio:

```text
/audio/volume ,f 0.8
```

Significa:

- Address:
  `/audio/volume`

- Type tag:
  `,f`

- Argomento:
  `0.8`

---

# ADDRESS PATTERN

Questa è una delle cose più geniali.

OSC usa percorsi stile URL:

```text
/player/1/position
/drums/kick/velocity
/ai/generate/chord
```

È praticamente un filesystem virtuale realtime. citeturn0search0turn0search2

---

# TYPE TAGS

Dopo l’address arriva la definizione dei tipi.

Esempi:

| Tag | Tipo |
|---|---|
| i | int32 |
| f | float32 |
| s | string |
| b | blob |

Esempio:

```text
,ifs
```

vuol dire:

```text
int + float + string
```

---

# ALLINEAMENTO A 32 BIT

Questa è una parte IMPORTANTISSIMA.

OSC richiede che tutto sia multiplo di 4 byte. citeturn0search0turn0search12

Perché?

Per velocità realtime.

Quindi:

- stringhe vengono paddate
- blob pure
- packets allineati

Questo rende parsing molto veloce nei sistemi audio realtime.

---

# BIG ENDIAN

OSC usa:

```text
big-endian
```

quindi:

- byte più significativo prima

Questo è importante se lavori:

- in C++
- JUCE
- socket raw
- binary serialization

Nel tuo progetto VST questo dettaglio conta tantissimo.

---

# BUNDLE

Qui OSC diventa fortissimo.

Un bundle permette:

```text
#bundle
[timestamp]
[messaggi multipli]
```

Quindi puoi sincronizzare eventi.

Esempio:

- kick
- luce
- visual
- animazione AI

tutti nello stesso timestamp.

---

# TIMETAG

OSC usa timestamp a 64-bit. citeturn0search0

Questo permette scheduling preciso.

Per AI audio generativa è enorme.

Potresti fare:

```text
/generate/chord
```

e schedulare output esatto nel beat futuro.

# UDP VS TCP

La spec dice:

- UDP naturale
- TCP possibile con size prefix citeturn0search0turn0reddit24

Nel realtime audio:

## UDP

pro:
- veloce
- low latency

contro:
- packet loss

---

## TCP

pro:
- affidabile

contro:
- latency/jitter

---

Per plugin musicali realtime:

- controllo realtime → UDP
- dati AI grossi → TCP/WebSocket

# LIMITI DI OSC

Importantissimo:

OSC NON definisce:

- autenticazione
- sicurezza
- discovery
- standard globale dei namespace

Quindi:

```text
/filter/cutoff
```

in un software può significare una cosa,
in un altro un’altra.

Questo viene citato spesso anche nelle discussioni tecniche reali. citeturn0reddit30turn0search6
